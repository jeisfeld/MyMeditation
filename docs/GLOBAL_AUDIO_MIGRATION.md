# Historical global sentence audio migration (retired)

The one-time converter and its Application startup hook were removed after migration completed on the intended device. The description below records how that conversion worked and the quality/recovery tradeoff. It no longer runs on startup. The former completion preference is unused. Existing migrated sources and saved entry metadata remain unchanged by removal.

## Formats and scope

- Previous format: version-1 manifests, full-script/settings identities (including speed), and numbered speed-rendered MP3s in each book directory.
- New format: version-2 manifests, version-3 identities, and global original-source clips keyed by sentence and effective synthesis settings. Native-provider speed is excluded; OpenAI's API speed remains in the key.
- Entry IDs, names, order, prompts, topic/text and pause guidance remain unchanged. `saved_speech_settings_<id>` preserves each entry's original voice/model/style/speed when books at different native speeds share one canonical identity.
- No text-generation or speech-generation endpoint is called by migration.

## Execution plan

1. On first launch, check the `global_sentence_migration_v1` completion preference. A fresh installation with no recording data completes immediately.
2. Reserve the audio-maintenance flag on main, then convert on a background thread. Playback/export/new recording attachments and Other-audio cleanup cannot race the conversion. Saved-entry deletion can still remove text/metadata, but physical audio cleanup waits; the main-thread commit never recreates links for a deleted entry.
3. Validate old manifests and their original identities. Preserve corrupt or unknown directories without guessing their settings. Do not follow symbolic-link recording directories.
4. First import available original provider-cache files for every known sentence. This pass takes priority across all legacy books so a baked copy cannot displace a known original.
5. Fill remaining missing clips from legacy numbered MP3s. Native speed 1 and OpenAI files can be copied; other native files are normalized with inverse speed once using the local decoder/Sonic/MP3 encoder. Sources generated by the new app are copied unchanged thereafter.
6. Publish each source atomically under its global key. Failed/cancelled temporary files never become valid clips. A retry reuses valid clips already published.
7. On the main thread, recheck current saved IDs and commit old-to-new recording links and saved synthesis snapshots in one preference transaction, only after file conversion succeeds. Missing/corrupt speech remains unavailable rather than being falsely marked offline.
8. Move old book directories to `files/legacy-sentence-audio/`, retaining the old manifests and numbered MP3s. After successful archive handling, commit the completion flag. Release maintenance and refresh availability.

Before the preference commit, interruption leaves the original links intact. After the commit, retries see the new links and reuse the already-published clips. The completion flag is never set for a failed conversion. An error keeps original files and asks the user to restart to retry. Unknown/corrupt directories are preserved; this migration cannot recover recordings whose metadata was already unreadable.

## Quality, space and recovery

If the original provider source still exists, the new clip is an unchanged copy. If only a previously stretched MP3 exists, its original sound cannot be recovered losslessly. Inverse stretching restores the nominal pace, but can add artifacts. Existing originals are therefore retained for review/recovery instead of being deleted by migration. The conversion also needs temporary free space for the new pool plus retained originals.

Migration backups are excluded from Android cloud backup and classified as **Other audio**. They are deleted only when the user confirms **Delete other audio**. Current sources referenced by any saved entry remain protected. Deleting these backups removes the old-format recovery copies; it does not remove the migrated saved audio. External shared MP3s are untouched.

If a manual rollback is required before backups are cleared, the old numbered files and version-1 manifests remain in each archived directory. Saved entries still retain their names/text/settings; their original speed is stored in `saved_speech_settings_<id>`. A rollback tool can derive the prior identity with `GlobalAudioMigration.legacyKey` from commit `97eb3652` and restore matching archived directories/links. Simply installing an older APK does not understand new links, so rollback must be explicit.

## Retirement and remaining data

The migration class, startup hook, migration-only tests and error message have been removed. Permanent global storage, original-source generation, local playback/export speed adjustment, and `CloudSpeech.cachedAudio` remain. Backup classification and Android backup exclusions remain so old archives can still be removed through Other audio. Installations that have not previously migrated their old per-book recordings are no longer automatically converted by this version.

## Replacing degraded normalized audio

Source files copied from the original provider cache did not undergo conversion. When only speed-baked MP3s existed, inverse stretching and MP3 encoding could introduce audible artifacts; the old recordings were retained as backups, not as recoverable lossless originals. If those migrated clips sound worse, freshly generated source audio is preferable. New recordings retain the provider's original source and apply speed only at playback/export.

Deleting **Other audio** removes retained backups, provider caches and unused pooled sources. It does not replace any migrated clip still pinned by a saved meditation. Shared clips may remain pinned by another saved entry even after Audio only is selected for one meditation.

For a guaranteed fresh-audio start using the existing UI, remove **Audio only** from every saved entry with audio, then **Delete other audio** in Additional settings. This preserves saved names, texts, prompts, order and retained speech settings, but deletes audio/recovery copies and requires normal provider charges for subsequent regeneration. Regenerate meditations gradually; matching newly generated sentences will be shared globally. This is a user-controlled cleanup procedure, not something executed by the migration-removal update.
